# 整机与服务联合补测协议（待硬件与服务条件填写后冻结）

日期：2026-09-22。状态：研究执行准备，**未采集新实验数据**。本协议服务于论文原有计算—电网问题；不把补测本身当作完整论文，也不承诺期刊级别。

## 1. 补测要回答什么

主要问题：在相同有效工作和任务质量、明确的完成期限、相同机器与信息条件下，功率控制是否降低完整观察时长的整机 AC 能耗；这个差异是否足以影响后续电网分析？

分别报告运行态能耗、完整窗口能耗、完成时间与服务违反、GPU 遥测能耗、设置与恢复开销。不用 GPU 占用时间代替有效工作或功率，不把降低平均功率直接称为节能。

## 2. 冻结前必须填入的事实

| 项目 | 必须留存的证据 | 未填写时的处理 |
|---|---|---|
| 硬件 | 同一节点 ID；CPU/GPU 型号及 GPU 数；拓扑、内存、互联、驱动/固件版本；全部 PSU 输入路径 | 不作共同硬件校准 |
| AC 边界 | 电表/仪器型号、量程、校准记录；所有 PSU 如何进入测量；共享负载及机房冷却是否在边界内 | 不使用“整机实测”表述；不得用名义 PUE 补成实测 |
| 工作负载 | 代码、模型、数据及配置内容哈希，精度、batch、序列长度、样本/请求清单、随机种子等 | 不能比较固定工作 |
| 有效工作 | 训练实际优化步及实际处理样本/有效 tokens；推理固定请求及输入/输出 token 数 | 不接受仅“相同运行时间”或“相同 epoch 标签” |
| 质量 | 事前指定评价集、指标、方向、非劣界及失败规则 | 不宣称固定服务或质量不变 |
| 服务 | 实际任务类别、合同或分析者期限、p95/p99/违约率等对应目标及阈值 | 分析者设定必须明示，不能写生产 SLA |
| 控制 | 允许的功率设置、是否作用于空闲卡、节点独占/共享、设置/恢复权限 | 不自行更改生产资源或共享节点设置 |
| 时间 | 电表/GPU/任务事件时钟、对齐方法、最大偏差与采样丢失标准 | 不作精确阶段归因 |

系统实际支持的控制范围需先核实。本协议不指定未经验证的绝对瓦数，也不执行硬件控制。

## 3. 实验结构

以“同一硬件、工作负载、活动 GPU 集合、工作清单、种子”为一组，先比较该组的正常设置与候选设置。不同硬件、卡数、模型分别建层，不直接合并为独立重复样本。

先导阶段用于测量变异、热稳定过程、采样频率需求和操作开销，并探索候选配置。确认阶段另取新运行批次，在看到其结果之前冻结候选、重复数/停止规则、质量界、服务界、异常与缺失处理。先导运行不能冒充确认样本。

在时间块内随机化设置顺序并配对正常设置，记录批次、顺序与随机化种子。跨时间块重复以观察漂移；若热状态或缓存状态有系统差异，显式设为因素或统一稳定条件，不能事后删除不利运行。重复数量按先导配对差异与目标置信区间宽度确定，不能因为得到显著性提前停止。稀有服务违反或尾延迟需要另行规划样本量；少量运行零超时不等于满足高分位服务要求。

跨所有政策保持相同工作、期限、可见信息与观察区间。即使某个模式失败、降频失败、质量未达标或超时，也保留其原始记录。候选在确认阶段失败时，不用已看过的确认数据重新选最优后继续称为确认结果。

## 4. 单次运行的记录顺序

1. 保存节点、后台任务与仪器状态；开始持续记录全部 AC 输入、各 GPU 遥测及单调时钟事件。
2. 测量初始空闲状态；若有预热，按固定规则执行并单独计能，不能把不同策略的成本选择性排除。
3. 记录控制请求、控制实际生效、工作开始、工作完成、质量检查、恢复请求和恢复完成。指令返回不等于功率已经稳定。
4. 运行正常或控制策略，记录全部工作与服务结果；发生异常继续保存日志，按预设恢复程序处理。
5. 回到预设共同终止状态，持续记录至共同观察区间结束。若研究允许关机或新任务接续，另设政策与反事实，不混入恒定空闲模型。

“控制额外能耗/时间”只计入基准运行与模式运行测量没有覆盖的部分；如果完整窗口积分已经包括设置与恢复，不得再次加上开销估计。

## 5. 交付数据

随附空表只定义结构，没有样例测量值，不应被运行程序识别为有效结果。

- `runs.csv`：每次运行一行，工作指纹、配对组、控制、观察区间、实际工作、质量、状态。
- `ac_power.csv`：统一时间坐标下所有测量输入的功率，逐通道保留；禁止同时相加总表与其子表。
- `gpu_power.csv`：所有已安装 GPU 的功率、控制设置及状态，包括未参与任务的卡。
- `events.csv`：控制、工作、恢复、质量检查的原始事件时间。
- `manifest_template.json`：硬件、测量边界、时钟、协议、质量和服务要求；空值表示尚缺证据。

仪器原始格式也须保留，转换后 CSV 不是唯一原始来源。文件清单记录字节数、SHA-256、工具版本和转换方法；身份字段可用稳定匿名 ID，保留跨表关联。

## 6. 验证与统计

先验证时间单调性、时钟对齐、覆盖完整性、采样间隔、缺失与重复、量纲及通道拓扑。对能量采用有记录的积分规则；边界插值必须在样本覆盖之内，不能外推补齐缺失。不能把仪器标称精度当所有时钟、积分、相位与边界误差的总界。

逐次检查有效工作相同与质量达标，再统计配对完整窗口能量差与服务指标。保留全部尝试的流程图：尝试、测量故障、工作失败、质量失败、超时、完整有效记录各多少；公布预设主分析与缺失敏感性，不能只统计成功节能的记录。相关的同一工作种子、节点和时间块不能作为互相独立的样本计算标准误。

均值能耗区间不替代单次服务保障。要么采用明确的概率服务约束并报告其不确定性，要么有能够支持确定上界的独立证据；生产任务的 p99 指标不能由运行时间均值和含义不明的标准差换算。

准入时同时满足：证据支持共同测量边界、工作与质量等价、预设服务要求、控制完整开销、确认数据上的效益。若未满足，结果保留为失败/不确定/局部测量，不能把期限调宽后沿用原 SLA 名称。

## 7. 如何接入论文

先形成同一硬件的工作负载—占用—控制—服务可行域及功率轨迹。仅在原任务硬件与放置可对应时接入真实任务回放；否则单独报告外部硬件情景。整机节能、用户电费、系统成本、容量与排放分别计算，不能相互代替。

已完成的省级旧结果继续作为历史条件诊断保存。修订主结果还需要真实机组承诺/供热、有效水量、同年份输入、固定投资样本外全年可靠性以及公平机制对照；补测通过不会自动关闭这些要求。
